# Durable paired-worker discovery transport

M-owned [claim #95](https://github.com/Akbarhoja/wrytely-agent/issues/95), branch `codex/canvas-discovery-journal`, base own #94 `8bc90b0a1041d6e8ba60df97ac88f5998718f2c1`. Existing pairing client privately supplies credentials, context/profile reads, bounded transport, trusted-context storage and the same per-storage operation lock. New discovery.mjs implements worker journal/recovery; app/shared/contracts/runtime/STATUS/CI are unchanged.

## Worker interface

- `beginDiscovery()` snapshots current context/profile and persists a stable begin key before dispatch.
- `commitDiscoveryPage({items,observed_at,coverage:{state,reason},next_cursor})` builds course-only C2 metadata from the verified binding and durable count/checkpoint. Caller cannot post actor, generation, connection or lease authority.
- `finishDiscoveryResource({resource_key,outcome,reason})` completes only observed terminal course metadata or honestly closes a selected academic resource with failure/unsupported coverage.
- `finishDiscovery()` preserves the backend aggregate; locally known open resources reject before an invalid intent is created.
- `resumeDiscovery()` journals/replays its own key and refreshes only the lease/checkpoint, retaining any pending primary capture. Pending begin must first be recovered to learn the scan ID.
- `retryDiscovery()` explicitly replays the exact pending capture/key. After a replaced/expired lease, explicitly resume then retry; only lease metadata is rebased. There is no automatic retry loop.
- `readDiscoveryStatus()` is a local safe projection without bearer, writer lease, cursor, subject or source payload. Operation results contain a private checkpoint cursor and closed-resource keys for a future trusted worker collector; do not bridge those results to UI/content scripts/model/logs.

## Durability and controls

The optional versioned journal is in the same atomic pairing record, not a second storage namespace. Intent is saved before the request, acknowledgment before returning. A storage failure never reports success; if a write committed before its failure surfaced, restart/recovery reads the actual stored state. Pairing cleanup/re-pair removes journal and credential together. An unresolved intent cannot be overwritten by another page or close operation.

Fresh existing context and Canvas profile checks bracket mutation/result, with expiry checked again after each awaited profile read. Mismatched connection/generation/scope/account stops old replay; unauthorized credentials clean up locally. Existing server leases/receipts remain authoritative. A resume response may reconcile the exact next checkpoint of a pending committed page; unexpected remote progress stops instead of inventing cumulative counts. Lost resume response retains its original key. Definitively rejected resume clears only the rejected renewal so an already committed finish can still be replayed; the primary intent remains.

The scan resource ledger is persisted separately from the changing catalog: initial selected resources plus acknowledged active-course additions in `all_active` mode. Missing/inactive courses cannot erase a still-open scan resource. Closure and finish use that durable ledger; incomplete acknowledgments prevent a false complete aggregate, and final receipts must contain exactly its resource keys.

Journal and finish-only replies are bounded8MiB; other discovery replies remain2MiB. Course envelope remains1MiB,50 items/page,100 pages,5000 cumulative records. The conservative Store maximum is(1000 initial+5000 discovered courses)*9 kinds+courses=54001 rows, not9001. Capacity correction was recorded before editing in[#95](https://github.com/Akbarhoja/wrytely-agent/issues/95#issuecomment-6548579542). Full4000-Unicode-codepoint cursors and maximum-size aggregate responses are supported; actual browser storage quota failures remain controlled and were not measured in live Chrome. Raw/unpaired-surrogate/NUL source strings reject before persistence; course-only exact fields prevent academic content injection. Returned projections never include bearer/lease or arbitrary response fields. Known terminal/open-resource states reject before creating an unrecoverable request.

The lock covers one worker realm sharing its storage object. Atomic single-record writes do not provide cross-realm transactional storage; the future installed host must own one journal writer. Server fencing rejects conflicting writers but does not reconstruct arbitrary missing local captures. Context changes, journal corruption, rejected captures or unexplained remote advancement deliberately stop for reconciliation; no automatic dropping/replacing of captured data is implemented. This is not a completed Chrome collector or scheduling host.
