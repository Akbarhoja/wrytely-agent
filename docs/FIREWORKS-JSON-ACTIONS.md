Post-submission candidate. No live configuration or model change is activated by
this option. Native mode remains default; no error triggers automatic fallback.

Operator setting `AGENT_FIREWORKS_ACTION_MODE=json` explicitly selects JSON-object
responses instead of the native `tools` parameter for the same fixed Meta Muse
Spark Open model. Meta still chooses the actions. The runtime still validates
typed decisions, source versions, permissions and budgets before executing them.
The OpenAI SDK remains transport only. No OpenAI inference, model router, second
agent, shell access or automatic provider swap is added.

The provider receives trusted action schemas and requests one JSON envelope:

```json
{"text":"","actions":[{"name":"record_course_decision","arguments":{}}]}
```

The example shows the envelope, not a valid course decision. Actual arguments must
still pass the original action-specific validator. Unknown names, extra envelope
fields, malformed/duplicate JSON keys, nonfinite values, invented call IDs, empty
responses and more than six actions fail closed. Caller IDs are assigned locally;
the model cannot choose an account, recipient or runtime attempt. Bounded canonical
history is validated before conversion. Prior action IDs and their untrusted
results are retained as distinct recorded-actions/result data so continuations
can correlate evidence. No encrypted Meta state is imported across providers.

The resulting ModelTurn uses the same canonical function-call contract as native
mode, so supervisor, drafting, checking and generic worker dispatch use their
existing Store and authorization checks. Text is not treated as an executed action.
Provider reasoning is excluded from the answer. No JSON parse or model failure
causes another inference; existing unknown-cost holds and blocked-task behavior
remain. Unsuccessful received-response usage is retained in controlled diagnostics.

JSON requests omit native tools and the provider-specific context-overflow option;
the converted request is bounded to250000 UTF8 bytes, far below the fixed model's
documented one-million-token context even at the16384 output maximum. The original
budget reserves the original history/schema bytes plus framing allowance and exact
output limit. JSON prompt overhead is bounded and covered by the existing allowance.
No setting increases an active budget or refills a grant.

Before any activation: pass exact combined CI and review, then separately approve
a synthetic JSON inference check. Only after that succeeds should a bounded
development course/recipient test be proposed. This candidate is not a successful
live workaround or completion of the autonomous student journey.
